## 1. Stack and build system

- **Framework:** Next.js 15 web app (`next@^15.5.18`, React 19, App Router,
  TypeScript). **Not** React Native, Expo, Flutter, Capacitor, or native
  Android. There is no `android/` directory, no Gradle project, no
  `eas.json`, no `capacitor.config.*` anywhere in the tree.
- **Package manager:** npm (`package-lock.json` present).
- **Hosting build:** OpenNext Cloudflare adapter — `npm run deploy` runs
  `opennextjs-cloudflare build && opennextjs-cloudflare deploy`
  (`package.json` scripts; Worker config in `wrangler.jsonc`).
- **Command that produces a release .aab:** **NOT FOUND in the repo.** The
  intended path (documented in `docs/PLAY_STORE.md`) is a Trusted Web
  Activity packaged *outside* the repo with Bubblewrap:
  `bubblewrap init --manifest https://foreman.coach/manifest.webmanifest`
  then `bubblewrap build`, which emits `app-release-bundle.aab`. No
  `twa-manifest.json` exists yet — Bubblewrap has not been run.
- **EAS:** not configured (no `eas.json`).
- **PWA prerequisites for the TWA are present:** `app/manifest.ts` (served
  at `/manifest.webmanifest`), icons in `public/icons/`, service worker
  `public/sw.js`, offline page `public/offline.html`, and
  `public/.well-known/assetlinks.json`.

## 7. Account deletion

**Fully present — both required surfaces.**

- **In-app:** Settings → "Danger zone" (`app/app/settings/page.tsx`,
  `app/app/settings/delete-account-form.tsx`) with a type-DELETE
  confirmation. Server action `deleteAccount` in
  `app/app/settings/actions.ts`: deletes the Stripe customer first

  `auth.admin.deleteUser` cascades through `profiles` into every

- **Web URL** (for the Data Safety form's deletion-URL field):
  **`/delete-account`** (`app/delete-account/page.tsx`) — public,
  explains the in-app steps and offers an email fallback
  (cfarriscoaching@gmail.com, 30-day promise).

## 9. Authentication and payments

- **Sign-in:** Supabase email + password (`@supabase/ssr` cookie sessions;
  `lib/supabase/*`, `middleware.ts` gates `/app` and `/onboarding`). No
  OAuth/social providers configured in code.
- **Trial:** every new account gets a 14-day full-access trial with no
  payment method (`subscription_status` default `'trial'`,
  `trial_ends_at now() + 14 days` — `supabase/migrations/0001_init.sql:23-26`).
  Expiry paywalls the app; nothing is auto-charged.
- **Selling inside the app: YES — via Stripe, not Play Billing.**
  Stripe Checkout for subscriptions ($19/mo, $169/yr —
  `app/api/stripe/checkout/route.ts`, `app/app/upgrade/`), plus one-time
  Stripe purchases for cohort seats (`app/api/cohorts/[slug]/checkout`)
  and 1:1 coaching sessions (`app/api/coaching/checkout`). A Stripe
  billing portal exists (`app/api/stripe/portal`). Google Play Billing is
  not integrated anywhere.
- **Consequence:** as a TWA, these purchase flows are reachable inside the
  Android app, which triggers Play's payments policy for digital goods.
  See Blocker #2.

## 10. Blockers

**Must fix before upload:**

1. **No Android artifact exists.** Bubblewrap has never been run — there is
   no `.aab`, no `twa-manifest.json`, no keystore. Run
   `bubblewrap init --manifest https://foreman.coach/manifest.webmanifest`
   (application ID `coach.foreman.app`) and `bubblewrap build` on a
   machine with a JDK; back up the generated keystore outside git.
2. **Play billing policy conflict.** Stripe checkout for digital
   subscriptions and purchases is reachable from every surface the TWA
   shows. Before submission either (a) hide/disable upgrade, cohort, and
   coaching checkout entrypoints when running inside the TWA (detectable
   via a start-URL parameter Bubblewrap can append), or (b) integrate Play
   Billing. Option (a) is the small change; submitting as-is risks
   rejection or takedown.
3. **`assetlinks.json` placeholder fingerprint.** `public/.well-known/assetlinks.json`
   still contains `REPLACE_WITH_SHA256_FINGERPRINT_FROM_PLAY_CONSOLE`.
   Sequence: first upload → copy the SHA-256 from Play Console → App
   signing → replace → redeploy. Until then the TWA shows a browser bar
   (works, but fails Play's polish bar and the TWA quality criteria).
4. **targetSdk unverifiable until packaging.** Confirm the generated
   project targets API 36+ before uploading (see §3).

**Should fix soon:**

5. **Closed-testing gate (if the developer account is personal):** ~12
   testers opted in for 14 continuous days before production access.
   Start recruiting now; this is the longest calendar item.
6. **Inconsistent `NEXT_PUBLIC_APP_URL` fallbacks.** Most routes fall back
   to `https://foreman.app` (e.g. `app/api/cron/daily-prompts/route.ts:88`,
   `app/api/stripe/checkout/route.ts:57`) while others use
   `https://foreman.coach` (`app/api/coaching/checkout/route.ts:44`) and
   the portal uses `http://localhost:3000`. If the env var is ever unset
   in production, emails and Stripe redirects point at the wrong domain.
   Unify on `https://foreman.coach`.
7. **Store listing assets are not in the repo** (fine, but required at
   submission): ≥2 phone screenshots, 1024×500 feature graphic, short/full
   descriptions. `public/icons/icon-512.png` serves as the 512×512 listing
   icon.
8. **Content rating questionnaire and target-audience declaration**
   (18+, no ads) must match the legal docs — straightforward, just not
   automatable from here.
